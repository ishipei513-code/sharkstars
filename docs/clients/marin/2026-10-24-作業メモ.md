### 2. 動きを追加

- **カーブコピーが波に乗って右から流れ込む**：`textPath` の `startOffset` を 150%（パス終端の外）

## 追記：セクションの繋ぎをアーチにした（13:11 デプロイ / 728feab）

参考：https://www.meisei.ac.jp/kg/

- **固定した写真の上を、次のセクションがアーチ型の縁で滑り上がる。**
  最初はステートメント側の下端にSVGの弧を置いたが、上を滑る staff セクションに
  完全に覆われていて**一度も見えていなかった**（staffTop=600 に対し arcTop=743）。
  弧は「滑り込む側の縁」に付ける。`.staff::before` に全幅の楕円
  （`border-radius:50% 50% 0 0 / 100% 100% 0 0`）を置くと、左右の角でセクションの
  上辺とぴったり合流して**一本の弧**になる。高さは px の clamp なので
  セクションの高さに左右されない（PC 92px / SP 40px）。
- ステートメントのコピーに `padding-bottom:clamp(56px,11vh,150px)` を入れて少し上へ。
  下の余白をアーチが先に通るので、特大見出しが弧で欠けて見えない。
- Instagramのモザイクは**上辺そのものを大円弧で切り抜いた**（`clip-path:url(#arcTop)`、
  `clipPathUnits="objectBoundingBox"`、`M0,0.21 Q0.5,-0.045 1,0.21`）。
  色面を重ねるのではなく写真を弧で切るのが参考サイトの使い方。
  ※ `padding-top` を足すと弧が写真に届かず効かない。

## 追記：画像が差し替わらなかった原因（重要）

スマホでヒーロー写真が変わらなかったのは**キャッシュ**。`?v=` を CSS/JS にしか
付けていなかったため、`images/hero-01-sp.webp` は中身を差し替えても古いまま出ていた。
ロリポップは `Cache-Control` を返さないので、ブラウザがヒューリスティックに長く保持する。

**縦の空白は線画では埋まらない。** 横の余白＝線画、縦の余白＝流れに乗る要素（波のライン）、
面全体＝にじみ、と役割を分けている。

### 散らしの位置決め（ここが肝）

**基準要素の中に入れて `top:100%`。** 兄弟として置いて static position に任せると、

- 親が grid だと静的位置がグリッド領域基準になる（採用CTAで発生）
- 段落の高さが親からはみ出していると基準がズレる（理念で phi-body が wrap より47px下まで伸びていた）

で想定外の場所へ飛び、実際に本文へ重なった。基準要素の下端からの px なら安定する。
`span` なので `<p>` の中にも入れられる。

**`z-index:-1` でカードや写真の背面に回す。** はみ出した分だけがチラッと見える＝
参考サイトの見え方になるうえ、万一ブロックに重なっても文字が読めなくなることがない。

2段の縦位置は実測した「基準要素の下の空き」に合わせて詰めた（スマホ390pxが最小なので、
そこに合わせれば全幅で安全）。

| セクション | 空き | セクション | 空き |
|---|---|---|---|
| 理念 | 49px | 採用CTA | 65px |
| 事業内容 | 33px | 利用者の声 | 91px |
| 選ばれる理由 | 38px | アクセス | 88px |
| はたらく人の声 | 120px | Instagram | 139px |

3つの入口だけは、カードが画面幅いっぱいに積まれて下端の余白が足りないので散らしを置かず、
光のにじみとガターの線画だけにした。
